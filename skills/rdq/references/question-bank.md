## 影片內容／YouTube

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| 觀眾打開影片的當下已經會什麼？ | 已在用 Claude Code／AI Agent 的重度使用者，可直接講指令、參數與踩坑 ／ 用過 ChatGPT 但沒碰過 Agent 或終端機，每個新名詞要先比喻 ／ 完全沒用過 AI，重點是「這跟我的課有什麼關係」／ 資訊組、主任、校長，關心資安、成本與可行性 | 觀眾層級猜錯，腳本密度、舉例與示範速度整份要重寫，不是換幾句話就能補救。 |
| 畫面裡會不會出現不該給外人看的？ | 只有我自己的螢幕與自製教材，全部可公開 ／ 有學生入鏡、學生作品或姓名，需家長同意或打碼 ／ 有主辦或他人的簡報、教材、Logo，需授權或改自製 ／ 會出現 API key、Firebase 設定、信箱、通訊軟體通知 | 這類東西通常是上片後被別人先發現的，一旦被截圖散布，下架也收不回來。 |
| 這支片是單支、系列、Shorts 還是直播？ | 單支 8–15 分鐘的獨立影片，講完一件事 ／ 3–6 集系列，每集約 10 分鐘，要統一片頭、封面模板、編號與播放清單 ／ 60 秒內 Shorts，或長片再切數支短片 ／ 60–120 分鐘直播，事後剪回放與精華 | 系列沒在第一集定好封面模板與命名規則，做到第三集回頭統一就前面全部重做；直播則腳本從頭不能寫成可重來的形式。 |
| 畫面怎麼來？這次要不要出鏡重錄？ | 螢幕錄影＋事後配音，人不出鏡 ／ 真人出鏡＋螢幕子母畫面，要打光收音，NG 就重錄 ／ 完全不新錄，用 AI 生成畫面與配音（draw／seedance／TTS）／ 直接重剪既有的直播或研習錄影 | 決定要不要寫逐字稿、要不要排錄影時段，後製工時可能差三到五倍；中途改成出鏡等於整支重來。 |
| 上架後誰看得到？之後還要在哪再用？ | 完全公開要衝觸及，需要標題、縮圖與 SEO ／ 未列出只發給研習學員，不衝點閱但連結要長期穩定 ／ 要在教室或研習現場投影播放，可能沒網路，需離線檔 ／ 要嵌進 HTML 簡報／駕駛艙／GitHub Pages，或當 NotebookLM 素材 | 未列出的片做 SEO 是白工，要現場播的片沒準備離線檔會當場開天窗，兩條路從一開始就分岔。 |
| 看完這支片，你要他當下做什麼？ | 什麼都不用做，知道有這回事、留下印象就好 ／ 暫停跟著操作一次，做出跟片中一樣的東西 ／ 轉給同事，或當研習的課前課後指定觀看 ／ 點描述欄連結去報名、下載或加入社群 | 「知道就好」和「跟著做」的片長、剪輯節奏、要不要做講義完全不同，剪到一半才改等於整支重剪。 |
| 字幕要硬燒、上 SRT，還是不做？ | 不做字幕，靠 YouTube 自動字幕 ／ 燒死在畫面上的硬字幕，手機靜音也看得到但之後不能改字 ／ 上傳 SRT 軟字幕，可關可搜尋、對 SEO 有幫助 ／ 需要中英雙語或另一種語言版本 | 硬字幕一旦輸出，改一個錯字就要重輸出全片，而且之後切直式 Shorts 時字幕位置會全部跑掉。 |

### Ⅳ 建議菜單（Unknown Unknowns）

- **上片前把螢幕錄影逐段掃一次敏感資訊：API key、Firebase config、分頁標題、桌面檔名、通訊軟體彈出通知、學生姓名** — 多一道 5–10 分鐘檢查；真抓到通常得局部打碼或補錄，但比公開後被人截圖便宜太多。
- **上傳時確認「是否為兒童打造」不要誤選——教學、校園題材很容易被順手標成兒童內容** — 只是一次判斷；但誤標會直接關閉留言、關閉訂閱者通知、無法加入播放清單，等於這支片的互動全斷。
- **背景音樂與素材只用 YouTube 音樂庫或授權明確的來源，並把授權證明存進專案資料夾** — 可選曲風變少；換來避免被 Content ID 認領——那不是下架，是收益直接被第三方收走，部分地區還可能被封鎖。
- **片中若有 AI 生成畫面或配音，或任何合作、贈品、業配，口頭講一句並勾選 YouTube 的合成內容與付費推廣揭露** — 多 1–2 分鐘設定與一句話；不揭露可能被平台自動加註或影響推薦，事後補救比一開始講清楚麻煩。
- **重要的教學片先設成「未列出」，發給 2–3 位老師試看 24 小時再公開** — 上線延後一天；但影片一公開就固定網址與數據，之後要改一個錯誤只能刪掉重上，留言與觀看數全部歸零。
- **開頭 5 秒直接放成品畫面＋一句「看完你會做出什麼」，封面文字壓在 4–6 個中文字，縮到 120px 寬自己確認還讀不讀得出來** — 剪輯順序要重排、封面通常得多做一版，約多 30 分鐘。
- **剪輯前就刻意設計 2–3 段能獨立成立的 45 秒內容，並在描述欄補上章節時間碼** — 腳本階段多花 20–30 分鐘設計切點、不能「講到哪算哪」；換來同一支片可直接切 Shorts、被老師跳段當教材、也更好餵進 NotebookLM。
- **描述欄不要寫死一堆會變動的連結，改成指向一個自己維護的入口頁（GitHub Pages 或一頁式資源清單）** — 多維護一個頁面；換來教材更新時不必動影片，也不會在頻道上留下一堆過期連結。

## 程式／網頁專案

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| 同一時間會有幾個人在用？ | 只有我一個人在講台上操作，學生看投影幕 ／ 全班約 30 人同時各自用手機或平板開 ／ 一場研習 100–300 人同時開，可能跨校 ／ 沒有現場使用，是我自己在電腦前跑的個人工具 | 併發人數決定要不要後端與資料庫；用單機思維做，全班同時送出會卡住或互相覆蓋，資料層要重做。 |
| 要不要呼叫 AI？金鑰由誰付錢？ | 完全不需要，純前端邏輯做得完 ／ 需要，但只有我用，金鑰我自己在本機輸入 ／ 需要，每台學生裝置都會呼叫，用我的金鑰付費 ／ 需要，但要求使用者自備金鑰貼進去 | 只要學生端會呼叫，金鑰就不能放前端，必須多一層代理；最後才發現等於重做部署與計費架構。 |
| 使用者輸入的東西，重整後還要在嗎？ | 用完即丟，重新整理就清空 ／ 同一台裝置同一個瀏覽器要記得住（localStorage）／ 任何裝置任何時間打開都要看到同一份（雲端資料庫）／ 還要能匯出成試算表或 CSV 給我事後登分 | 這條直接決定有沒有資料庫、資料模型怎麼設計；事後才說要跨裝置，等於整個存取層重寫。 |
| 需要分辨「這筆是誰送的」嗎？ | 完全不用，只看全班統計，純匿名 ／ 學生自己打座號或暱稱，我信任他不會亂打 ／ 要一組活動代碼或共用密碼擋住外人 ／ 要真的 Google 帳號登入，身分不能造假 | 身分層是資料模型的地基，也牽動個資責任；先做匿名再改實名，前端、資料庫結構與安全規則全部要動。 |
| 你打算怎麼把這東西交到使用者手上？ | 一個 HTML 檔，雙擊或用隨身碟就能開，不需要網路 ／ 部署到 GitHub Pages，發網址或 QR Code ／ 需要一台一直開著的伺服器（Node／Python）／ 掛進既有專案或網站底下當子頁面 | 決定能不能純靜態；做完才發現需要藏金鑰或跑後端，部署架構要整組換掉。 |
| 最爛的情況會是什麼裝置、什麼網路？ | 教室單槍電腦、Chrome、網路穩定 ／ 學生自己的手機（含舊 Android、iOS Safari），直式螢幕 ／ 研習現場共用 Wi-Fi，兩百人同時連可能塞 ／ 有機會完全沒網路，要能離線運作 | 版面、字級與同步機制都由這條決定；照桌機做完再改手機直式，通常是重排整個版面而不是微調 CSS。 |
| 有沒有既有的東西一定要接、且不能改？ | 沒有，從零開始，資料結構我可以自由設計 ／ 有現成 Google 試算表或 CSV，欄位不能動 ／ 要接既有專案（html-slide-builder／teaching-cockpit／既有 Firebase），沿用原結構 ／ 產出要餵給別的系統（校務行政、Padlet、NotebookLM） | 既有欄位會反過來綁死資料模型；自己先設計一套漂亮結構，最後還是得補一層轉換甚至打掉重來。 |

### Ⅳ 建議菜單（Unknown Unknowns）

- **金鑰有三個常被忽略的外洩管道：前端 JS（按 F12 就看得到）、git commit 歷史（刪檔也還在）、公開 repo；先做 .gitignore ＋ repo 設私有，學生端要呼叫 AI 就改走 Cloud Functions／Workers 代理** — 多一層部署與一次設定（約 30–60 分鐘），免費額度內不花錢，但架構從純靜態變成靜態＋代理。
- **若會呼叫 AI API，先設用量上限：單次字數限制、每人每日次數上限、優先用最便宜的模型，並開 billing 警示** — 回答長度與品質受限，要多寫一段計數邏輯；換來不會發生一節課學生亂玩燒掉幾百塊。
- **若用 Firebase：預設測試模式規則等於任何人都能讀寫全部資料，且免費方案每日讀寫有天花板；一開始就寫好安全規則並估算大場研習的讀寫次數** — 多花約半小時設定，之後改資料結構要同步改規則；但可避免研習中途被寫爆或被惡意灌資料。
- **只要蒐集姓名、班級座號就進入個資範疇；改用當場產生的代號或流水碼，並設定活動結束後自動刪除或手動清空** — 事後就無法做個別學生的長期學習分析；要留就得走學校的家長同意流程。
- **實際拿一台 iPhone 和一台舊 Android 測過再上場：iOS Safari 無痕模式的 localStorage、自動播放音訊、剪貼簿權限行為都不同，同時備 QR Code 加短網址** — 多 20–30 分鐘實測；漏掉的常見結果是現場一半學生打不開或按鈕點不到。
- **為現場準備斷線備案：一個不依賴網路、雙擊就能開的單檔 HTML（砍掉即時同步），或紙本／PDF 替代活動** — 要多維護一個精簡版本，兩邊改動時要同步；但教室網路掛掉時整堂課不會停擺。
- **從第一版就做一個「一鍵匯出 JSON／CSV」按鈕，把資料層與畫面層分開寫** — 多花約半小時；換來免費服務改政策或停止營運時，資料能整包帶走而不是重打。
- **把可調參數（題目、班級、Firebase 設定、顏色）集中到單一 config 檔，加一頁 README 寫清楚「怎麼改題目、怎麼重新部署、金鑰放哪」** — 前期多花 30–60 分鐘拆結構寫文件；受益者除了其他老師，主要是半年後已經忘光的你自己。

## 硬體／機構／射頻跨部門整合設計

> 這段對應強固型（rugged）硬體產品的研發總監視角：同時統籌硬體、機構、射頻三組，決策發生在「三邊系統性互動」的交界，而不是單一部門內的技術深度。題目來源：連接器選型踩過的雷（系列有 Receptacle 無對應 Plug）、開模比價流程、防水組裝方式取捨、軍規／防爆認證的設計前置要求。

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| 這次要符合哪一套電源／EMC規範？ | 車用 ISO 7637＋CISPR25（民用車規）／ 軍規 MIL-STD-1275＋MIL-STD-461（電壓與突波等級更高）／ 沒有外部規範，只要過公司內部驗證／ 客戶另外指定規範，還沒拿到文件 | 規範等級決定電源的箝制架構、元件耐壓與驗證流程複雜度，兩套規範拓樸完全不同，做完才換等於整顆電源重新設計。 |
| 這個連接器規格，兩端型號都查過了嗎？ | 已指定系列，Plug 與 Receptacle 都確認有對應型號 ／ 已選系列但只查到一端（如只有 Receptacle），另一端還沒查 ／ 還在比較廠牌，沒指定系列 ／ 客戶或上層系統已內定，機構只能配合 | 連接器系列可能存在缺一端的情況（如某系列只有 Receptacle 沒有 Plug），選到最後才發現要客製或換供應商，機構外殼與 PCB 接口設計得跟著重改。 |
| 機殼外觀定案前，RF 淨空有跟 RF 對過嗎？ | 天線位置與淨空已跟 RF 確認過，外觀定案不影響訊號 ／ 外觀還在設計中，RF 還沒介入看過 ／ 這款沒有天線／無線需求，不需要 RF 淨空 ／ 沿用舊款外殼，假設淨空沒問題但沒重新驗證 | 外觀與機構先定案、天線效能事後才測，若 RF 不過，通常要重開模具或加開孔，是整個專案最貴的返工之一。 |
| 防水／密封要靠什麼組裝方式達成？ | 點膠／灌膠（不可拆，防水等級最高，維修要整組報廢）／ 上下蓋＋螺絲鎖固加膠條（可拆，防水等級中等）／ 卡勾＋膠墊（組裝快，防水等級較低）／ 這個部件不需要防水 | 組裝方式決定良率、維修性與防水等級的取捨；開模後才想換組裝方式等於重開模具，且已投產的良率數據全部作廢。 |
| 開模／打樣要比價嗎？時程還有多久？ | 已有多家報價，準備發包 ／ 只問過一家，還沒比價 ／ 沿用舊模具或現成料件，不需要開新模 ／ 時程很趕，可能要跳過比價直接發包 | 模具修改一次的時間與費用都很高，沒比價可能多花冤枉錢；時程若真的要跳過比價，得先跟上層講清楚風險，不能默默省略。 |
| 這是防爆／特殊環境認證產品嗎？ | 一般商規產品，無特殊環境認證 ／ 需過 MIL-STD-810 環境測試（溫度／振動／衝擊）／ 需過防爆認證（如 ATEX／IECEx zone0/1），內部須隔絕火花與熱源 ／ 尚不確定，客戶還沒明講要哪一張證 | 防爆認證要求的灌膠、雙層防護等設計手法要在測試前就內建進結構，事後才追加認證等於重新設計整個機殼與內部佈局。 |
| 這份規格／設計要送誰簽核？ | 我（總監）內部核准即可 ／ 需要 EE／ME／RF 三組主管都簽過才能定案 ／ 需要送客戶或最終用戶審查確認 ／ 需要走正式的 design review 會議並記錄在案 | 簽核範圍沒先問清楚，事後被要求補簽或重新審查時，常常已經開始打樣或發包，回頭改的成本比先問一句高很多。 |

### Ⅳ 建議菜單（Unknown Unknowns）

- **連接器選型時，同時查 Plug 與 Receptacle 兩端的實際料號，不要只看系列名稱** — 多花時間逐一核對料號，但能避免選到系列名稱存在、實際某一端缺貨的窘境。
- **讓 RF 介入的時間點要早於「外觀 100% 定案」，哪怕只是先給一塊天線淨空的粗略保留區** — ID／外觀要接受一塊不能隨意佔用的區域，犧牲一點造型自由度，換掉外觀完稿後才發現訊號不過關、要重開模具的風險。
- **開模廠商比價時，除了報價，順便問「修模一次的費用與工期」，不是只比首次開模價** — 多問一個問題；修模往往比首次開模更貴更慢，這才是決定總成本的關鍵。
- **材料規格定案後才跑結構模擬（push force、應力等），材料還沒定案前先用經驗值估可行性就好，不要提前跑完整模擬** — 模擬只能到定案後期才開始，前期決策要靠經驗值先抓可行性；換掉的是「材料一改、模擬全部重跑」的重工。
- **跨三組（HW／ME／RF）的案子，在外觀定案前就約三邊主管一起看一次，而不是各自做完再對** — 早期多一次三方會議，換掉外觀定案後才發現彼此衝突、要拆掉重排的風險。
- **軍規／客戶指定規範文件到手後，先用 `design-check-list` skill 跑一次章節／Shall 語句抽取，不要單靠記憶手動整理需求表** — 多一道腳本執行的步驟，但能系統化抓出人工三輪覆核都可能漏掉的缺口（已有實測案例驗證：手動三輪稽核漏了 3 個真實缺口，工具抓到了）。

## 研發管理與技術分析

> 這段對應研發主管視角：處理的不是單一技術問題，而是「這件事要不要做、做完給誰看、用什麼節奏推進」。題目來源：策略層／執行層要用不同決策節奏（八面鏡矛盾2裁決）、部屬曾主動反映「質疑放最前面」讓團隊不敢說話（團隊管理溝通風格回饋案例）、身兼兩個部門（GVS 產品／Global ECO System Center 生態系）需要先釐清脈絡、技術規範比較報告（如 MIL-STD-1275 vs ISO7637）要先定比較基準。

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| 這次要交付的是決策，還是分析／比較報告？ | 只要我自己想清楚，不用寫成文件 ／ 要一份給團隊／部屬看的分析文件 ／ 要一份能直接呈報上級的匯報文件 ／ 要能直接發給客戶或生態系夥伴看的正式文件 | 對象不同，用語、保密程度與下判斷的力道完全不同；寫給自己看的分析拿去對客戶，會外洩內部判斷過程；呈報上級的文件只列現象不給結論，會被打回票重寫。 |
| 這是策略層決策，還是執行層決策？ | 策略層（部門方向、技術路線圖、要不要投入新領域）——沒有立即截止日，容易一直拖 ／ 執行層（規格判定、跨組資源取捨）——需要馬上拍板，但拍板前要先告知相關人 ／ 兩者都有，牽動部門方向也要馬上決定 ／ 還不確定，需要先釐清 | 策略層決策要設 deadline 逼自己做，執行層決策要先告知再快速拍板；用錯節奏，策略議題會無限期擱置，執行議題會因沒先告知讓人措手不及。 |
| 這份技術分析要對比幾個方案／規範？比較基準是什麼？ | 只有一個方案，是要說明它、不是要比較 ／ 兩三個方案並列比較，要選出建議方案 ／ 要對比現行規範與新規範的差異與合規負擔（如軍規 vs 民用規範）／ 純粹整理知識庫，暫時不需要下建議 | 沒先定比較基準（成本？時程？合規門檻？），分析做完才發現比較的維度不是決策者在意的，等於重新選基準再分析一次。 |
| 這件事會不會被部屬解讀成「質疑」？ | 純技術討論，對事不對人，直接講重點就好 ／ 涉及某人負責的工作成果，開頭需要先肯定，再講需要調整的地方 ／ 是團隊已知的敏感議題，要先私下一對一再公開討論 ／ 不涉及任何人的工作表現，是純制度或流程問題 | 過去「質疑放最前面」已經讓部屬覺得溝通不健康、開會不敢講話；同樣內容換個開場順序，結果會完全不同。 |
| 這件事屬於哪個部門／哪頂帽子？ | GVS，硬體／機構／射頻的產品本身 ／ Global ECO System Center，生態系夥伴、Solution Roadmap、跨廠商整合 ／ 兩邊都有關聯，需要同時考慮 ／ 還不確定，這是新議題 | 兩個部門雖共用同一位上級，但評估邏輯不同（產品規格 vs 夥伴生態），搞混脈絡容易在匯報時答非所問。 |
| 對外或對上呈現，要親自上場還是委派？ | 我自己講，內容我熟、風險我能當場回答 ／ 委派給team裡較適合的人，我事前把關內容 ／ 用書面文件取代口頭報告，不需要即時問答 ／ 還沒決定，先看場合正式程度 | 臨時才決定要不要委派，代表人可能沒把關過內容重點與風險點，正式場合的臨場落差會被放大。 |
| 有沒有截止日？需要排進固定決策時段嗎？ | 今天就要有結論 ／ 這週內排進固定決策時段處理即可 ／ 沒有明確期限，屬於長期持續累積的議題 ／ 已經拖了一段時間，這次要強制設一個截止日 | 沒有排進固定時段或截止日的策略性議題，過去的模式是會被無限期擱置——不是忘記，是「沒有被排進流程的事就不會發生」。 |

### Ⅳ 建議菜單（Unknown Unknowns）

- **策略性議題固定排進每天的「決策時段」，而不是等有空再想** — 多一項每天的固定行程；但這是唯一被驗證對你有效的方法，靠意願提醒過去都沒用。
- **開場先講「這件事做得好的地方」，把要調整的意見放在後面，尤其是針對某人負責的工作** — 每次多花 10–20 秒鋪陳；換掉部屬因為「質疑放最前面」不敢主動發言的風險。
- **需要對外或對上呈現前，先確認「這次是我親自講，還是我把關內容讓別人講」，不要臨場才決定** — 早一點決定要多安排一次內容討論；但能避免委派對象上場時內容不熟、風險沒準備。
- **分析或比較報告先問清楚要交給誰看（自己／部屬／上級／客戶），再決定要不要下建議結論** — 多一步確認；但能避免寫給自己看的分析被直接轉發給上級或客戶，暴露還沒篩選過的判斷過程。
- **這件事若同時牽動兩個部門，先明講是哪一頂帽子的議題，或兩頂都要** — 多一句釐清；但能避免用產品規格的邏輯去談生態系議題（或反過來），讓討論失焦。
- **策略層決策設 deadline，執行層決策先告知再快速拍板，不要用同一套速度處理** — 需要意識切換兩套節奏；但用錯節奏會讓策略議題無限期拖延、執行議題讓人措手不及。

## 通用（無對應領域時的 fallback）

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| 這東西做完之後，最後會到誰手上？ | 只有我自己用，不會給別人看 ／ 給我認識的固定一群人（我班上 30 人、同校 5 位老師），我可以當場口頭說明 ／ 給不特定的人自己操作，我不在現場 ／ 要交給主辦、上級或評審審查，須符合指定格式 | 事後才發現要公開或被審查，防呆、使用說明、授權與版面全部得補，等於整份重做。 |
| 有沒有「絕對不能發生」的狀況或規定？ | 沒有特別限制，做壞了重做就好 ／ 不能動到現有檔案，只能新增，原檔要保持原樣 ／ 內容不能外流（學生個資、成績、未公開題目、他人素材）／ 有明文規定要遵守（學校資訊組管制、主辦資安規範、平台條款） | 覆蓋原檔、外流個資這類事做錯無法回頭，代價遠高於重做一次。 |
| 這個成果最後要在哪裡被打開或執行？ | 只在我自己的電腦上開，本機檔案就好 ／ 傳給別人在他們的裝置上開（手機、平板、學校電腦）／ 在研習或教室現場投影播放，網路不保證穩 ／ 放到網路上長期存取（GitHub Pages、雲端連結） | 預設有網路做出來的東西，在沒網路的教室或別人的手機上直接開不起來，現場沒有第二次機會。 |
| 什麼時候要有能用的東西？有死線嗎？ | 今天、這次對話結束就要能拿去用 ／ 這幾天內（本週）完成就好 ／ 有一個不能動的固定日期（研習、段考、上片、直播當天）／ 沒有死線，做好比做快重要 | 死線抓錯會做出「來不及完成的完整版」，最後被迫在活動前一天砍掉重練。 |
| 這件事可以花錢嗎？上限在哪裡？ | 完全不能花，只能用免費方案或現有帳號 ／ 可用我已在付的訂閱（Claude、OpenAI），但不另開新服務 ／ 可自費小額（幾百元內），例如 API 呼叫費、生圖費 ／ 有單位預算可核銷，但要走報帳流程 | 用了付費方案才發現不能花錢，工具選型與整個實作方式得整組換掉。 |
| 怎樣算做成功？用一句可驗收的話說。 | 我自己看過覺得可以就算成功 ／ 別人不用問我，照著就能自己完成 ／ 要達到具體數字或事實（40 人在 10 分鐘內都完成、檔案能成功上片）／ 要通過特定的人或單位審查、符合指定規定或格式 | 沒先講好驗收標準，做完才說「不是我要的」，而不合的通常是整體結構而不是細節。 |
| 這是一次性任務，還是之後還會重複做？ | 只做這一次，做完就結束 ／ 之後可能再做類似的，但我會自己手動改 ／ 每學期、每場活動都要做一次，希望這次就做成可直接套用的模板 ／ 除了我以外，還要讓其他老師拿去用 | 一次性寫法事後要改成可重複套用幾乎等於重寫；反過來為一次性任務過度模板化則是白花時間。 |
| 現在的起點是什麼？有現成的可以接嗎？ | 完全從零開始，沒有任何現成材料 ／ 有一堆零散素材（舊簡報、PDF、筆記、逐字稿）但沒整理 ／ 有一個做到一半的版本，要接著往下做 ／ 有上一版成品，這次是改版翻新，要保留原架構 | 不知道已有半成品或舊版，會做出跟現有東西不相容的新版本，兩邊最後都得再整合一次。 |

### Ⅳ 建議菜單（Unknown Unknowns）

- **先花十幾分鐘做一版「所有段落都在、細節從簡」的粗胚給你看方向，確認後再精修** — 第一版看起來很陽春，但把方向做錯的代價從「整份重做」降到「改一次大綱」。
- **幫這件事準備一個「壞掉時怎麼辦」的備案：離線可用的版本、靜態截圖或純文字稿，現場斷網或登不進去時直接切換** — 多花 20–30 分鐘準備一份備份，換掉現場開天窗的風險。
- **交付前先掃一遍有沒有學生姓名、成績、可辨識照片或他人授權素材；要公開就換成假資料或先去識別化** — 多一道檢查與可能的素材替換，但個資或著作權出事之後補救不回來。
- **現在就明講「這次不做什麼」，把想到的加分功能收進第二階段清單，不要邊做邊加** — 這次成果會比想像中陽春，但能準時收尾，也不會做到一半卡在半成品。
- **動手前先盤點有沒有現成的可以直接改——你自己已有的 skill、舊專案、公開模板，而不是從零再造** — 多花 5–10 分鐘盤點，可能省掉一整輪從零開發；代價是沿用舊架構有時會帶進舊限制。
- **成果不要只留在對話裡，同步落到既有三處（Google Drive 專案資料夾、GitHub、Obsidian），並在筆記寫下「這次做到哪、下一步」** — 多幾個指令與一次 commit，換掉換電腦或幾週後回來找不到、被迫重問一輪的風險。
- **做完後把這次的流程與決定整理成可重複套用的模板（或直接長成一個 skill）** — 這次多花 20–40 分鐘收尾，之後每次省掉重問一輪需求、重搭一次架構。

## 領域判定

Phase 0 靜默判定用。**以「這次真正要交付的成品」選主段**；一個任務可能同時命中兩段（例：研習用的互動簡報），此時主段全讀、另一段只挑補充題，概念重複的只問一次。

| 任務長相 | 領域段 | `domain` 值 | 常見交棒 |
|---|---|---|---|
| 要拍、要剪、要上片：YouTube 影片、Shorts、直播回放、上片素材 | 影片內容／YouTube | `video` | `yt-pack`、`seedance`、`draw` |
| 要寫程式、要部署、要收資料：互動網頁、小工具、Firebase 應用 | 程式／網頁專案 | `dev` | 自己執行，或接既有專案 |
| 要出硬體／機構／射頻的產品規格、跨部門整合設計、連接器／材料／模具／認證等決策 | 硬體／機構／射頻跨部門整合設計 | `hwmerf` | `design-check-list`（規格轉需求表）、自己執行 |
| 要做研發／部門管理決策，或技術規範／方案的分析比較報告 | 研發管理與技術分析 | `rdmgmt` | 自己執行，或先出分析文件再交棒 |
| 以上皆非、跨多類難以歸屬，或還看不出成品形態 | 通用 | `general` | 視訪談結果再定 |

判定不確定時預設 `general`，並在第一輪多附一題確認產出形態；判定錯誤的成本遠低於問錯方向的成本。

## 寫你自己的領域段

上面幾段涵蓋影片內容、程式專案、硬體跨部門整合設計、研發管理與技術分析，皆非特定教學現場專屬。你若在別的領域（法律、醫護、電商、製造、行銷、非營利…），照下面的方法補一段自己的。

**先確認你真的需要補**——`video`、`dev` 兩段跨領域幾乎照用。真正該補的是你那行**外人不會知道的雷**。

### Ⅲ 訪談題怎麼寫

每一題都要通過這個測試：**「這題答案不同，做法真的會重做嗎？」** 過不了就別收——答案怎樣都行的問題只是在浪費對方的時間。

| 欄位 | 要求 |
|---|---|
| 題幹 | ≤25 字，口語，**不夾帶建議**（建議是 Ⅳ 的事） |
| 選項 | 2–4 個，**具體到可直接寫進規格**。寫「開庭前三天」不要寫「時間緊」；寫「客戶是第一次打官司」不要寫「不熟悉流程」 |
| | 涵蓋光譜兩端，不可只列你偏好的方向（防錨定） |
| 不問會怎樣 | 一句話寫**踩雷後果**。這欄是排序依據，也是整份題庫最值錢的地方 |

「不問會怎樣」寫得出來，代表你真的踩過；寫不出來，這題大概不是紅燈題。

### Ⅳ 建議菜單怎麼寫

格式：`- **<一句話建議>** — <一句話代價／影響>`

- 必須是對方**真的可能沒想到**的：不可逆決定、法遵與資安紅線、這類事情失敗最常見的原因、他不知道存在的替代方案
- **每條都要標代價**（多花時間？多花錢？增加複雜度？）——不標代價就變成推銷
- 人人都知道的事不要收
- 5–8 條，寧缺勿濫

### 範本

```markdown
## <你的領域名>

### Ⅲ 訪談題（Unknown Knowns）

| 題幹 | 選項 | 不問會怎樣 |
|---|---|---|
| <≤25 字，具體> | A ／ B ／ C | <踩雷後果，一句話> |

### Ⅳ 建議菜單（Unknown Unknowns）

- **<建議>** — <代價／影響>
```

補完記得到「領域判定」表加一列：任務長相、領域段名稱、`domain` 值（小寫英文）、常見交棒對象。

### 最快的補法

不用一次寫完。**跑幾次真實任務，把當下真正卡到你的問題記下來，回填。** 這份題庫本來就是這樣長出來的——每一條「不問會怎樣」都是有人真的踩過才寫得出來。
